### §3.2 fs API → Vercel Blob SDK 매핑

**기존** (consent-form.tsx:48-71):
```typescript
import fs from 'fs'
import path from 'path'
// ...
try {
  const logsDir = path.join(process.cwd(), 'logs', 'consent')
  fs.mkdirSync(logsDir, { recursive: true })
  fs.writeFileSync(
    path.join(logsDir, `${alphaCode}.json`),
    JSON.stringify(consentRecord, null, 2),
    'utf8',
  )
} catch {
  // 로그 저장 실패는 동의 완료 흐름에 영향 주지 않음
}
```

**마이그레이션 후** (설계):
```typescript
import { put } from '@vercel/blob'
// (fs, path import 제거)
// ...
try {
  await put(
    `consent/${alphaCode}.json`,
    JSON.stringify(consentRecord, null, 2),
    {
      access: 'public',          // 또는 'private' (v13 §10 PII 정책 정합 위해 'public' 비추천 → 'private' 권고)
      addRandomSuffix: false,    // 동일 alpha_code 재제출 시 덮어쓰기 보장
      contentType: 'application/json',
    },
  )
} catch {
  // 로그 저장 실패는 동의 완료 흐름에 영향 주지 않음 (기존 동작 보존)
}
```

**핵심 매핑 1:1 정합**:
- `fs.mkdirSync` → 불필요 (Blob 디렉토리 개념 없음, prefix만)
- `fs.writeFileSync` → `put` (단발 async 호출)
- `logs/consent/<code>.json` → `consent/<code>.json` (prefix 패턴 유지)
- `try/catch` 동일 패턴 유지 (저장 실패 시 사용자 흐름 무영향)
