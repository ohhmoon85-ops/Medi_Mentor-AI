### §3.2 (α) 전략 채택 시 동시성 위험 분석

**시나리오 — 동일 type 동시 POST**:
1. 사용자 A: POST → `get('metrics/M3_emergency_routing.jsonl')` 결과 `existing_A`
2. 동시 사용자 B: POST → `get('metrics/M3_emergency_routing.jsonl')` 결과 `existing_B` (= existing_A)
3. A: `put(existing_A + line_A)`
4. B: `put(existing_B + line_B)` → **line_A 손실** (B의 put이 A를 덮어씀)

**알파 5명 × 1~2주 트래픽 기준 TPS 추정**:
- 1명당 라우팅 결과 페이지 진입 ≈ 1~3회/일
- 5명 합산 ≈ 5~15회/일 ≈ **TPS 0.0002**
- 동시 POST 충돌 가능성 매우 낮음 (수학적 추정 1% 미만)

**손실 영향**:
- 메트릭 1건 누락 → 통계 정확도 미세 저하
- 응급 라우팅·진료 안내 무관 (메트릭은 후처리 데이터)
- 알파 단계 허용 가능 위험

**LAUNCH-0 시점 강화 권고** (발주문 §0 외부): 외부 메트릭 서비스 (Sentry/PostHog) 또는 DB queue 이전.

### §3.4 fs API → Vercel Blob SDK 매핑

**기존** (`route.ts:37-47`):

```typescript
try {
  const dateStr = new Date().toISOString().slice(0, 10)
  const logsDir = path.join(process.cwd(), 'logs', 'metrics')
  mkdirSync(logsDir, { recursive: true })
  const logPath = path.join(logsDir, `${dateStr}.jsonl`)
  appendFileSync(logPath, JSON.stringify(record) + '\n', 'utf8')
} catch (e) {
  console.error('[metrics] 파일 저장 실패:', e)
}
```

**마이그레이션 후** (설계, α 전략):

```typescript
import { put, list } from '@vercel/blob'

// ...
const pathname = `metrics/${record.payload.metric_type}.jsonl`
const newLine = JSON.stringify(record) + '\n'

try {
  // 기존 NDJSON 읽기 (404 시 빈 문자열)
  let existing = ''
  try {
    const result = await list({ prefix: pathname })
    const target = result.blobs.find((b) => b.pathname === pathname)
    if (target) {
      const res = await fetch(target.url)
      if (res.ok) existing = await res.text()
    }
  } catch {
    // 첫 적재 — 새 Blob 생성
  }
  // read + append + write (NDJSON 형식 보존)
  await put(pathname, existing + newLine, {
    access:          'public',
    addRandomSuffix: false,
    contentType:     'application/x-ndjson',
  })
} catch (e) {
  console.error('[metrics] Blob 저장 실패:', e)
}
```

**핵심 매핑**:
- `mkdirSync` → 제거 (Blob 디렉토리 개념 없음)
- `appendFileSync(path, line + '\n')` → `list` + `fetch` + `put(existing + newLine)`
- `application/x-ndjson` Content-Type 으로 JSONL 형식 명시 보존
- `try/catch` 기존 동작 보존 (저장 실패 시 API 응답 정상)
- `console.error` 디버깅 로그 보존
