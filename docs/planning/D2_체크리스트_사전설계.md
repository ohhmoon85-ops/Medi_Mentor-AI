### 1단계 — 대분류 선택 (카드 그리드)

## 4. Decision Rules — 3단 계층 분기

### 4.1 1단 — 위급 신호 우선 검사 (⚠️ 트리거)

체크된 항목 중 위급 신호가 있으면 즉시 KTAS L1~L2 분기, 다른 분석 생략:

```typescript
const URGENT_TRIGGERS = {
  // L1 (즉시 응급)
  L1: [
    { signals: ['h_thunderclap'], possible: ['뇌출혈', '뇌동맥류 파열'] },
    { signals: ['h_neck_stiff', 'h_consciousness_low'], possible: ['뇌수막염', '뇌출혈'] },
    { signals: ['h_face_palsy', 'h_speech_slur'], possible: ['뇌졸중'] },
    { signals: ['c_chest_pain_crush', 'c_cold_sweat'], possible: ['심근경색'] },
    { signals: ['c_dyspnea_sudden'], possible: ['폐색전증'] },
    { signals: ['s_anaphylaxis'], possible: ['아나필락시스 쇼크'] },
    { signals: ['a_pain_sudden', 'a_vomit_blood'], possible: ['위장관 천공'] },
  ],
  // L2 (15분 이내)
  L2: [
    { signals: ['a_pain_rlq'], possible: ['충수염'] },
    { signals: ['c_chest_tight'], context_required: 'severity:심함', possible: ['협심증'] },
    { signals: ['a_stool_black'], possible: ['상부 위장관 출혈'] },
    { signals: ['c_phlegm_blood'], possible: ['폐결핵', '폐암 의심'] },
  ]
};

function checkUrgent(checkedSymptoms: string[], context: Context): UrgentMatch | null {
  for (const trigger of URGENT_TRIGGERS.L1) {
    if (trigger.signals.every(s => checkedSymptoms.includes(s))) {
      return { ktas: 1, ...trigger };
    }
  }
  // L2도 동일 검사
  return null;
}
```

### 4.2 2단 — 부위 + 증상 조합 매칭

위급 신호 없으면 부위(대분류) 안에서 체크된 증상 조합 매칭:

```typescript
const COMBINATIONS_HEAD = [
  {
    name: '편두통',
    required: ['h_headache_unilateral'],
    supporting: ['h_headache_stab', 'h_photo_phobia', 'h_nausea'],
    score_threshold: 2, // required 1개 + supporting 1개 이상
    ktas: 4,
    specialty: 'NEU',
    supplements: ['mag_b2', '오메가3'],
  },
  {
    name: '긴장성 두통',
    required: ['h_headache_general'],
    supporting: ['h_headache_squeeze'],
    contradictions: ['h_headache_unilateral'],
    score_threshold: 1,
    ktas: 5,
    specialty: 'FM',
  },
  {
    name: '부비동염',
    required: ['h_headache_general'],
    supporting: [/* '코막힘' (다른 카테고리 동시 체크 시) */],
    ktas: 4,
    specialty: 'ENT',
  },
];

function matchCombinations(region: string, checked: string[]): Match[] {
  // 점수 계산, 매칭 2~3건 반환
}
```

### 4.3 3단 — 매칭 없음 시 일반 안내

체크 항목이 너무 적거나 매칭 점수 부족 시:
- KTAS L4 또는 L5
- 가정의학과 (FM) 추천
- "증상이 일반적이지 않습니다. 가정의학과에서 종합 상담을 권장합니다." 안내

### 4.4 LLM 보조 (선택)

체크리스트 결과 + 자유 입력 한 줄을 LLM에 전달 → 자연어 응답 생성. 단:
- decision rules가 결정한 KTAS·진료과·가능성을 **고정 입력**으로 LLM에 전달
- LLM은 자연어 표현만 생성, 결정은 변경 금지
- 톤: 의사 자식 톤 (친근하지만 정확)

## 6. Vision (D1) 결합 방식

피부 + 외상(팔·다리 일부) 카테고리에서 자연스러운 사진 첨부 유도:

```
[피부] 선택 시:
"📷 사진을 첨부하면 더 정확한 안내가 가능합니다 (선택)"
"피부 발진·점·외상은 시각 분석이 효과적입니다"
```

```
[팔·다리·관절] 외상 항목 체크 시:
"📷 상처 사진을 첨부하면 응급도 판단에 도움됩니다"
```

다른 카테고리는 사진 첨부 버튼 미표시 (효용 낮음):
- 머리·얼굴: 외상 항목 시에만
- 목·가슴: 미표시 (외관 진단 어려움)
- 배·소화: 미표시
- 눈·코·귀: 눈 외관 + 목 안쪽 시 표시
- 비뇨·생식: 미표시 (개인정보·민감)
- 전신·기분: 미표시

→ Vision 권장 카테고리만 사진 입력 UI 노출 = 효용 + 개인정보 보호 양립

## 8. D2 발주 시점 모듈 분할 후보

D2 복합 발주는 G5 / D1과 비슷한 규모로 예상 (6~8 모듈):

| 모듈 | 작업 | 라인 (예상) |
|---|---|---|
| **D2-1** | `lib/checklist/` types + regions + symptoms 카탈로그 | ~500 |
| **D2-2** | `lib/checklist/` urgent-triggers + combinations + conditions | ~950 |
| **D2-3** | `lib/checklist/` decision-engine + prompt + index | ~225 |
| **D2-4** | `app/api/checklist/route.ts` 신설 (Vision 결합 포함) | ~150 |
| **D2-5** | UI: region-grid + symptom-checkboxes + context-input | ~400 |
| **D2-6** | UI: result-card + 라우팅 (/care/check 신규) + 랜딩 분기 | ~250 |
| **D2-7** | 면책 강화 (§8.9 재실행) — disclaimer 7번째 항목 추가 ("체크리스트 결과는 추정") | ~30 (보호 해제) |
| **D2-8** | §15 후처리 + v16 인계 문서 작성 (Claude Code 또는 orchestrator 분담) | 문서 |

총 신규/변경 약 2,500라인. **본 프로젝트 최대 단일 발주**가 될 가능성 큼.

대안: D2를 **D2 + D3 두 사이클로 분할**:
- D2: lib/checklist/ 데이터 + decision engine + API (백엔드)
- D3: UI 컴포넌트 + 라우팅 + 면책 강화 (프론트엔드)

분할 권장: G5(584줄/6모듈)에서 commit 단위 부담 인지된 경험 정합.
