>

## 1. 프로젝트 정체성 (Care와 공통)

### 1.1 한 줄 정의 (기획서 v2)

MediMentor AI는 환자에게는 "1차 의료 안내자"가 되고, 의사에게는 **"24시간 옆을 지키는 임상 멘토"**가 되어 주는, 전 세계 의료 지식을 통합한 양방향 AI 진료 지원 플랫폼이다.

### 1.2 Pro 사용자 정체성

medimentor Pro는 **한국 1차 진료 의사**(개원의·봉직의 포함)를 대상으로 한다.

- **Care와 페르소나 완전 분리**: 환자(Care) ↔ 의사(Pro)
- **Pro의 가치 제안**: "환자가 우리 의원에 더 잘 준비된 상태로 오게 도와주는 도구" + "임상 의사결정 지원(CDSS)"
- **사용 시나리오**: 진료 직전·중·후 활용 가능한 의사 단말 도구

### 1.3 Pro의 핵심 차별화

- 기존 시장 플레이어: UpToDate(임상 가이드라인), Lexicomp(약물 정보), 국내 EMR(메디블록 등)
- medimentor Pro의 차별화:
  - 한국어·한국 의료 환경 특화 (보험급여, 한국형 가이드라인, KIMS 약물 정보)
  - Care와 연동된 환자 도착 전 정보 (환자가 Care에서 작성한 증상 일기·복용약·체크리스트가 의사 단말로 전달)
  - "임상 멘토 모드" — 신참 의사·드문 케이스 시 근거 기반 권고

### 1.4 Care와 Pro 아키텍처 분리 (K-5)

| 측면 | Care | Pro |
|---|---|---|
| 사용자 | 환자/가족 | 1차 진료 의사 |
| 채팅 | 본 인계 v6 | 본 인계 v1 (Pro) |
| 코드베이스 | lib/care/, lib/safety/, lib/specialty/ 등 | lib/pro/ (신규) |
| 라우트 | /care/* | /pro/* (인증 필요) |
| 인증 | 익명 가능 | 의사면허 인증 필수 |
| LLM 모델 | Claude Sonnet (claude-sonnet-4-6) | TBD (CDSS 정확도 검증 필요) |
| 규제 | 의료법 제27조 무면허 의료행위 회피 | CDSS 규제 검토 별도 |
| 외부 의존성 | 카카오맵 외부 링크 | 의사협회 API, UpToDate/Lexicomp 라이선스 |

### 1.5 의도적으로 "하지 않는 것" (Pro 영역)

| 제외 기능 | 사유 |
|---|---|
| 의사 대리 처방 발행 | 의료법 위반 |
| 환자 진단 단정 자동화 | CDSS 보조 도구 정체성 위반 |
| 의사면허 미인증 사용 허용 | Pro 정체성 핵심 |
| 보험 청구 자동화 | 별도 사업 영역 (메디블록 등) |
| EMR 대체 | EMR과 연동, 대체 아님 |

## 3. P1 의사 인증 인프라 (Phase 1 출발점)

### 3.1 P1 범위

| 항목 | 내용 |
|---|---|
| 인증 방식 | 의사면허번호 + 의사협회 면허 확인 API 검증 |
| 식별 정보 | 면허번호, 이름, 전공, 소속 의원/병원 |
| 세션 관리 | NextAuth + JWT (Care와 분리된 세션) |
| 라우트 보호 | /pro/* 전체에 미들웨어 적용 |
| 다중 로그인 | 단일 면허번호 동시 세션 제한 |
| 미인증 차단 | /pro/* 접근 시 /pro/auth로 리다이렉트 |

### 3.2 외부 의존성 — 사용자 직접 협상 영역

**의사협회 면허 확인 API**:
- 사용자(문형철)가 의사협회 또는 보건복지부 협상 진행
- 코드는 mock/stub으로 시작하여 실제 API 연동 시 교체 가능한 구조로 설계
- 면허 확인 비용·약관·이용 절차는 협상 결과에 따름

**Pro 진입 시 의사협회 API 미확보 시 대안**:
- 옵션 A: 의사면허증 사진 업로드 + 수동 검증 (베타 출시 가능)
- 옵션 B: KAIM(대한의사협회) 회원 인증 연동
- 옵션 C: 의료기기·진단지원 SaaS 동종업계 검증 절차 참조

### 3.3 P1 작업 구조 (Care 패턴 C 위임 적용)

```
[신규 파일]
lib/pro/auth/license-validator.ts        — 면허 확인 인터페이스 (mock + 실제 API 분기)
lib/pro/auth/session-manager.ts          — JWT 세션 관리
lib/pro/auth/types.ts                    — DoctorIdentity 인터페이스
middleware.ts (확장)                      — /pro/* 보호
app/(pro)/auth/page.tsx                  — 인증 페이지
app/(pro)/auth/api/route.ts              — 인증 API
app/(pro)/dashboard/page.tsx             — 인증 후 대시보드 (P2~ 진입점)

[보호 파일 — Care 코드 변경 금지]
lib/care/* (M5 6파일)
lib/safety/* (단계 A·B 보호)
lib/specialty/* (M3-1 ~ M3-4 + M4)
lib/shared/llm-client.ts (M6, Pro도 재사용 가능)

```

## 4. P2 감별진단 엔진

### 4.1 P2 범위

| 항목 | 내용 |
|---|---|
| 입력 | 의사가 입력한 환자 증상·검사 결과 + Care에서 전달된 환자 사전 정보 (선택) |
| 출력 | 감별진단 후보 (확률·근거·추가 검사 권고) |
| LLM | UpToDate/Lexicomp RAG + 한국어 가이드라인 |
| UI | 의사 단말 친화 (정보 밀도 높음, 키보드 단축키, 표 중심) |

### 4.2 P2 핵심 결정사항 (Pro 채팅 진입 시 확정 필요)

- **CDSS 규제 분류**: 의료기기 등급 검토 필요 (식약처 자문 필수)
- **임상 라이선스**: UpToDate/Lexicomp 한국 라이선스 협상
- **출처 추적성**: 모든 권고에 인용 의무 (P6 연동)
- **단정 표현 정책**: Care와 다름. Pro는 의사 판단을 보조하므로 진단 후보 명시 가능 (단, 최종 판단은 의사 책임)

### 4.3 외부 의존성 — 사용자 직접 협상

**임상 데이터 라이선스**:
- UpToDate (Wolters Kluwer)
- Lexicomp (Wolters Kluwer)
- 또는 KAMC(한국의학교육평가원) 가이드라인
- 또는 자체 RAG 구축 (한국 진료지침)

**규제**:
- 식약처 의료기기 등급 자문
- ISMS-P 인증 (의사 정보 + 환자 정보 통합 처리)

## 10. Care와의 연동 지점 (Pro 채팅 진입 시 확정)

### 10.1 환자 사전 정보 전달 (M5 → Pro)

**Care 측 산출물 (M5)**:
- 증상 일기 카드 (의사 요약)
- 복용약 목록 (텍스트 + 사진)
- 진료과별 체크리스트

**Pro 측 수신 인터페이스 (P2 진입 시 설계)**:
- 환자가 Care에서 클립보드 복사한 텍스트 paste 입력
- 또는 (Phase 2) QR 코드/공유 링크로 직접 전달
- 또는 (Phase 3) EMR 통합 (P7)

### 10.2 동기화 정책

- Phase 1: 일방향 (Care → Pro). Pro에서 Care 데이터 조회 미운영
- Phase 2: 환자 동의 시 양방향 (Pro 진단 결과 일부를 Care 일기에 자동 기록)

### 10.3 개인정보 보호

- Care 데이터는 환자 단말 로컬 저장 우선 (Phase 1)
- Pro에 전달 시 환자 명시 동의 필수
- ISMS-P 사전 준비는 Pro 진입 시 본격화

## 13. 작업 패턴 (Care와 동일)

### 13.1 검증된 작업 패턴 — 패턴 C (I-1)

Care에서 자가 패치 0건 연속 5회 달성한 패턴 C를 Pro에서도 적용:

- 임상 안전 등급별 차등 위임
- 사용자 페르소나(의사) 단말 도구이므로 환자 안전 등급보다는 **의사 의사결정 신뢰도**가 핵심 안전 기준
- LLM 출력 검증은 "출처 인용 + 의사 최종 판단" 이중 안전장치

### 13.2 보고 형식 의무화 (K-3 단축 회신)
