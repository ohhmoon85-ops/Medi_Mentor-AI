## 1. 프로젝트 정체성

### 1.1 한 줄 정의 (v2 기획서 기준)

MediMentor AI는 환자에게는 "1차 의료 안내자"가 되고, 의사에게는 "24시간 옆을 지키는 임상 멘토"가 되어 주는, 전 세계 의료 지식을 통합한 양방향 AI 진료 지원 플랫폼이다.

### 1.2 medimentor 사용자 정체성 (E-1, 2026-05-02 재정의)

medimentor는 "노년층 대상 의료 AI"가 아니라 **"한국 가정 누구에게나 필요한 가정 주치의 안내자"**이다.

- **노년층**: 가장 취약한 1차 고려 대상이지만 유일 사용자가 아님. 빈발 증상 가중치 유지.
- **전 연령 시나리오 정식 지원**: 영유아·소아·청장년·임산부·노년 모두 커버.
- **가족 단위 3인칭 입력 정식 지원**: "내 아이가", "부모님이", "남편이" 등 입력자 ≠ 환자 시나리오. 단계 A·B의 1인칭 가정 로직(`capturedDemographics`)은 변경 없이 보존하고, M3-2/M3-3에서 3인칭 패턴 그룹 및 가족 인구학 라우팅을 별도 추가한다.

본 정체성 재정의는 M3-1 작업 검토 중 발견되었으며, 50개 증상 작성 기준·연령군 분포·표현 중립화에 직접 영향을 준다.

### 1.3 브로드 추천 정책 (G-1, 2026-05-02 도입)

medimentor는 닥터나우·굿닥의 단정적 병원 추천("이 병원으로 가세요")과 차별화하여 "안내자형 메시지"("이런 진료과들 중 가까운 곳으로 가세요")를 채택한다.

- 환자에게 `secondary_specialties`와 `tertiary_specialties`를 적극 노출
- 추천 문구 형식: "OO과를 우선 권합니다. ~한 경우 OO과·OO과도 고려하실 수 있습니다."
- "1차 의료 안내자" 정체성에 부합하는 환자 선택권 보장 정책
- M3-2의 50개 entries 매핑 작성 시 `secondary_specialties` 적극 활용 의무
- M3-3 추천 로직, M3-5 UI 구현에도 일관 적용

본 정책은 사용자 결정으로 medimentor 전반 정책으로 격상되었다. 닥터나우·굿닥 차별화 정책과 정합하며, 광고비 의혹·의사 신뢰 확보 전략을 강화한다.

### 1.4 현재 작업 범위

- **Care MVP 우선 개발 중** (옵션 D 채택)
- **Pro(의사용)는 Phase 2 이후 분리 진행** (면허 인증 인프라 등 진입 장벽 큼)
- 기획서 Phase 1 (M4~M9) 일정 안에 Care MVP 베타 출시 목표

### 1.5 의도적으로 "하지 않는 것" (변경 불가 결정사항)

다음 결정은 medimentor의 신뢰성 차별화 전략이며 변경하면 안 된다.

| 제외 기능 | 사유 |
|----------|------|
| **위치 기반 병원 추천 알고리즘** | 닥터나우·굿닥과 차별화. AI가 특정 병원 추천 시 "광고비 낸 병원" 의혹 발생 가능. 의사용 Pro 사업의 의사 신뢰 확보에 결정적 영향 |
| 진단 단정 표현 | 의료법 제27조 무면허 의료행위 회피. "OO일 가능성이 있습니다"만 사용 |
| 처방 정보 환자 직접 제공 | 약사법·의약분업 위반 |
| 원격 진료 행위 | 의료법 제34조 회피 |
| 병원 후기·평점 알고리즘 | 의료광고법 시비 가능성 |

### 1.6 차별화 포지셔닝

- 기존 시장 플레이어: 닥터나우(병원 추천·예약), 굿닥(병원 검색)
- medimentor의 차별화: "증상 해석 + 진료과 안내 + 자가관리"에 정체성을 좁힘
- 의사용 Pro는 "환자가 우리 의원에 더 잘 준비된 상태로 오게 도와주는 도구"로 포지셔닝

## 3. 단계 A·B 검증 매트릭스 (마감)

총 127개 시나리오 100% 통과. 누계:

- 단계 A 단일 턴 임상 경고 (16개)
- 단계 A 단일 턴 일상 호소 차단 (12개)
- 단계 A 복합 매칭 (3개)
- 단계 B-1 디바운싱 (8개)
- 단계 B-1-Δ 클라이언트/서버 일관성 (36개)
- 단계 B-1-Δ-2 다중 턴 인구학 (7개)
- 단계 B-2 경고 강도 (15개)
- 단계 B-3 입력 유지 + 119 버튼 (17개)
- 단계 B-4 119 직통 종합 (13개)

추가로 M3-1 + M3-1-fix 검증 시나리오 35개 통과 (M3-1-1~18 재검증, M3-1-19~23, M3-1-fix-1~9, M3-1-policy-1~3, TypeScript 0 errors 포함).

### 3.1 양방향 회귀 차단 달성

| 오류 유형 | 대표 사례 | 차단 방법 |
|----------|---------|---------|
| Type II (놓침) | SAH 환자 → 일반 안내 | 4개 SAH 패턴 추가, 형태론 보강(아프→아파), 다중 턴 인구학 컨텍스트 공유 |
| Type I (과경고) | "두통이 좀 있어요" → critical | 단독 키워드 패턴 제거, 복합 패턴(임상 위험 수식어 + 카테고리)만 유지 |

### 3.2 황 교수님 임상 자문 컨펌 4가지 UX 결정

1. **디바운싱**: 1.5초 정지 + 5자 미만 보류
2. **경고 강도**: 3단계 차등(critical/urgent/high) + 음성 자동 재생 critical 한정
3. **입력 잠금**: 옵션 B (입력 유지) + critical/urgent 시 119 버튼 상시 노출
4. **119 직통**: 옵션 B (원탭 호출, 자동 다이얼 금지, tel:119 표준 링크)

## 4. 5단계 트리아지 시스템 현황

기획서 정의(5단계) vs 단계 A·B + M3-1 구현 현황 비교:

| 기획서 등급 | TriageLevel enum | 의미 | 구현 상태 |
|-----------|------------------|------|----------|
| 🔴 즉시 응급 | `critical` | SAH, 흉통+호흡곤란 등 | ✅ 단계 A·B 완료 + M3-1 50개 중 5개 |
| 🟠 응급 | `urgent` | 심한 복통, 고열+의식 흐림 | ⚠️ 단계 A·B 부분 + M3-1 50개 중 10개 |
| 🟡 야간/주말 | `night_weekend` | 응급 아닌 심한 통증·발열 | ❌ M4에서 추가, M3-1에서는 0개 |
| 🟢 일반 외래 | `outpatient` | 수일~수주 지속 일반 증상 | ⚠️ M3-1 50개 중 15개 (M4에서 일부 night_weekend 재분류 예정) |
| 🔵 자가 관리 | `self_care` | 경미한 증상 | ⚠️ M3-1 50개 중 20개 |

**중요**:
- M3-1-fix에서 `TriageLevel` 5단계 enum이 정식 도입되어 인터페이스가 준비되었음
- `night_weekend`는 M4 모듈(야간주말/자가관리 분기)에서 `outpatient`/`urgent` 일부를 재분류하여 채울 예정
- 단계 A·B의 3단계 UI(critical/urgent/high)는 환자 경고용 표시 레벨이며, M3-1의 5단계 enum은 데이터 분류 레벨로 별개 체계임. M3-3/M3-5에서 두 체계를 연결할 예정

## 5. 다음 작업 예정 (우선순위 순)

### 우선순위 1: M3-2 진료과 매핑 (다음 코딩 작업)

- 50개 증상 × 진료과 매핑 사전 작성 (의료자문 검증 전 초안)
- **브로드 추천 정책 의무 적용**: `primary_specialty` 1개만 채우지 말고 `secondary_specialties` 적극 활용 (2개 이상)
- **1인칭/3인칭 패턴 그룹 분리**: `patterns` 필드를 1인칭("나는 ~", "내가 ~")과 3인칭("아이가 ~", "남편이 ~", "어머니가 ~") 두 그룹으로 명확히 분리 작성
- `recommendation_reason` 형식: "OO과를 우선 권합니다. ~한 경우 OO과·OO과도 고려하실 수 있습니다."
- 예상 기간: 2~3주

### 우선순위 2: M3-3 추천 우선순위 로직

- 1차/2차/3차 추천 우선순위 로직
- red_flag classifier critical 시 `emergency:true` 진료과로 강제 라우팅
- 그 외 시 `primary_care:true` 진료과 중에서 1차 추천
- 가족 인구학 라우팅 (3인칭 입력 → 환자 인구학 추출 → `family_demographics` state 신설 검토, `capturedDemographics` 무변경)
- 카카오맵 외부 링크 (병원 추천 알고리즘 미운영)
- 예상 기간: 2~3주

### 우선순위 3: M3-4 LLM fallback

- 정적 사전 매칭 실패 시 LLM fallback
- 클라이언트/서버 일관성 검증
- 예상 기간: 1~2주

### 우선순위 4: M3-5 UI 통합

- 카카오맵 외부 링크 UI
- 환자용 추천 근거 설명 UI (브로드 추천 메시지 형식 적용)
- 예상 기간: 1~2주

### 우선순위 5: M4 야간주말/자가관리 분기

- 5단계 트리아지 확장 (current 4단계 + `night_weekend` 0개 → outpatient/urgent 일부 재분류)
- 달빛어린이병원·야간진료 가능 의원 정보
- 자가관리 안내 (대증요법, 생활습관, OTC)
- "하지 말아야 할 것" 명시
- 예상 기간: 3~4주

### 우선순위 6: M5 방문 전 안내

- 증상 일기 카드 자동 생성
- 복용약·영양제 등록
- 준비물 체크리스트
- 예상 기간: 2~3주

### 우선순위 7: M6 공통 시스템 보강 (병행)

- M6.5 의학용어 일상어 자동 병기
