## §5 ALPHA-0 임시 비상 운영 1페이지 (C-7 inline)

본 §5는 LAUNCH-0 P-2(b) 24h 핫픽스 SOP 본격판(v13 §11 A1, v13 §5.3 대기)이 작성되기 전까지의 **임시** 비상 운영 가이드. ALPHA-0 종료 시점에 본 §5는 폐기되고 A1 본격 SOP로 대체된다.

### 5.1 kill switch 토글 절차

**전제**: 알파 진입점은 알파 코드 게이팅 + 환경 변수 기반 feature flag로 통제된다 (C-5 산출).

**즉시 차단 절차** (목표 SLA: 토글 결정 → 차단 완료 5분 이내)

1. 사용자(문형철)가 사고 인지 또는 orchestrator 권고 수령.
2. 배포 환경 feature flag 토글 (예: `ALPHA_GATE_ENABLED=false`).
3. 배포 환경 재기동 또는 hot-reload 적용.
4. 알파 코드 5개 전부 진입 차단 확인 (테스트 1건 즉시 수행).
5. §5.2 회수 메시지 발송 (사고 유형).

**검증 방법**: 알파 코드 1개로 진입 시도 → 차단 화면 노출 + 라우팅 응답 없음.

### 5.2 알파 5명 일괄 회수 메시지 템플릿

### 5.3 사고 보고 흐름 (3 단계)

```
[1단계] 알파 사용자 → 문형철
         ↓ 채널: N3 피드백 진입점 (1순위) / 사전 약속 직통 채널 (2순위)
         ↓ 보고 내용: 알파 코드 + 발생 시각 + 입력 요약 + 받은 안내 + 우려 사항
         
[2단계] 문형철 → Claude orchestrator
         ↓ 채널: 본 채팅 또는 후속 채팅 (v13 정합 보존)
         ↓ 보고 내용: 1단계 원문 + 사고 분류 의견 (Type II 의심 / 시스템 오류 / 비기능 불만)
         
[3단계] Claude orchestrator 권고
         ↓ 3-1. kill switch 즉시 토글 권고 여부 (Type II 의심 시 무조건 토글)
         ↓ 3-2. 사고 분류 확정 + 재현 시나리오 추출
         ↓ 3-3. 핫픽스 분기 권고:
                  - 단발 패치 (가벼운 버그)
                  - G-복합 발주 (정책 회로 수정 필요)
                  - 알파 종료 (구조적 결함)
         ↓ 3-4. 회수 메시지 템플릿(§5.2) 권고
```

**24h SLA 임시 목표**: 1단계 수신 → 3단계 권고 완료까지 24시간 이내. P-2(b) 본격 SOP 도입 전 임시 운영. 실측 시간은 ALPHA-0 운영 중 메트릭으로 누적 → A1 작성 시 참고 자료로 활용.

- 본 §5는 **임시** 가이드이며, LAUNCH-0 진입 직전 A1 본격 SOP로 대체된다.
- 본 §5는 알파 5명 규모를 가정한 운영. 공개 출시 규모에서는 채널·메시지·SLA 모두 재설계 필요.
