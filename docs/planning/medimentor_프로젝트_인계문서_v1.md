## 1. 프로젝트 정체성

### 1.1 한 줄 정의 (v2 기획서 기준)

MediMentor AI는 환자에게는 "1차 의료 안내자"가 되고, 의사에게는 "24시간 옆을 지키는 임상 멘토"가 되어 주는, 전 세계 의료 지식을 통합한 양방향 AI 진료 지원 플랫폼이다.

### 1.2 현재 작업 범위

- **Care MVP 우선 개발 중** (옵션 D 채택)
- **Pro(의사용)는 Phase 2 이후 분리 진행** (면허 인증 인프라 등 진입 장벽 큼)
- 기획서 Phase 1 (M4~M9) 일정 안에 Care MVP 베타 출시 목표

### 1.3 의도적으로 "하지 않는 것" (변경 불가 결정사항)

다음 결정은 medimentor의 신뢰성 차별화 전략이며 변경하면 안 됩니다.

| 제외 기능 | 사유 |
|----------|------|
| **위치 기반 병원 추천 알고리즘** | 닥터나우·굿닥과 차별화. AI가 특정 병원 추천 시 "광고비 낸 병원" 의혹 발생 가능. 의사용 Pro 사업의 의사 신뢰 확보에 결정적 영향 |
| 진단 단정 표현 | 의료법 제27조 무면허 의료행위 회피. "OO일 가능성이 있습니다"만 사용 |
| 처방 정보 환자 직접 제공 | 약사법·의약분업 위반 |
| 원격 진료 행위 | 의료법 제34조 회피 |
| 병원 후기·평점 알고리즘 | 의료광고법 시비 가능성 |

### 1.4 차별화 포지셔닝

- 기존 시장 플레이어: 닥터나우(병원 추천·예약), 굿닥(병원 검색)
- medimentor의 차별화: "증상 해석 + 진료과 안내 + 자가관리"에 정체성을 좁힘
- 의사용 Pro는 "환자가 우리 의원에 더 잘 준비된 상태로 오게 도와주는 도구"로 포지셔닝

## 3. 단계 A·B 검증 매트릭스 (마감)

총 127개 시나리오 100% 통과. 누계:

- 단계 A 단일 턴 임상 경고 (16개)
- 단계 A 단일 턴 일상 호소 차단 (12개)
- 단계 A 복합 매칭 (3개)
- 단계 B-1 디바운싱 (8개)
- 단계 B-1-Δ 클라이언트/서버 일관성 (36개)
- 단계 B-1-Δ-2 다중 턴 인구학 (7개)
- 단계 B-2 경고 강도 (15개)
- 단계 B-3 입력 유지 + 119 버튼 (17개)
- 단계 B-4 119 직통 종합 (13개)

### 3.1 양방향 회귀 차단 달성

| 오류 유형 | 대표 사례 | 차단 방법 |
|----------|---------|---------|
| Type II (놓침) | SAH 환자 → 일반 안내 | 4개 SAH 패턴 추가, 형태론 보강(아프→아파), 다중 턴 인구학 컨텍스트 공유 |
| Type I (과경고) | "두통이 좀 있어요" → critical | 단독 키워드 패턴 제거, 복합 패턴(임상 위험 수식어 + 카테고리)만 유지 |

### 3.2 황 교수님 임상 자문 컨펌 4가지 UX 결정

1. **디바운싱**: 1.5초 정지 + 5자 미만 보류
2. **경고 강도**: 3단계 차등(critical/urgent/high) + 음성 자동 재생 critical 한정
3. **입력 잠금**: 옵션 B (입력 유지) + critical/urgent 시 119 버튼 상시 노출
4. **119 직통**: 옵션 B (원탭 호출, 자동 다이얼 금지, tel:119 표준 링크)

## 4. 5단계 트리아지 시스템 현황

기획서 정의(5단계) vs 단계 A·B 구현(3단계) 비교:

| 기획서 등급 | 의미 | 단계 A·B | MVP 추가 필요 |
|-----------|------|---------|--------------|
| 🔴 즉시 응급 | SAH, 흉통+호흡곤란 등 | ✅ 완료 | - |
| 🟠 응급 | 심한 복통, 고열+의식 흐림 | ⚠️ 부분 | 미착수 |
| 🟡 야간/주말 | 응급 아닌 심한 통증·발열 | ❌ 미착수 | **반드시 추가** |
| 🟢 일반 외래 | 수일~수주 지속 일반 증상 | ❌ 미착수 | 미착수 |
| 🔵 자가 관리 | 경미한 증상 | ❌ 미착수 | **반드시 추가** |

**중요**: 현재 critical/urgent/high 3단계는 🔴/🟠/🟢 매핑이며, 🟡 야간주말과 🔵 자가관리가 통째로 누락되어 있음.

## 5. 다음 작업 예정 (우선순위 순)

- 기존 황 교수님 docx의 표지/서문 수정

- 예상 시간: 30분~1시간

### 우선순위 2: M3 진료과 매칭 모듈 (다음 코딩 작업)

- 26개 진료과 정의
- 증상 → 진료과 매핑 사전 구축
- 1차/2차/3차 추천 우선순위 로직
- 추천 근거 설명 ("이 증상은 ○○ 가능성이 있어 ○○과를 우선 추천")
- 카카오맵 외부 링크 (병원 추천 알고리즘 미운영)
- 예상 기간: 2~3주

**핵심 결정사항 (M3 시작 전 결정 필요)**: 매핑 사전을 LLM이 생성하게 할지, 의료자문 검증한 정적 사전을 만들지

### 우선순위 3: M4 야간주말/자가관리 분기

- 5단계 트리아지 확장 (3단계 → 5단계)
- 달빛어린이병원·야간진료 가능 의원 정보
- 자가관리 안내 (대증요법, 생활습관, OTC)
- "하지 말아야 할 것" 명시
- 예상 기간: 3~4주

### 우선순위 4: M5 방문 전 안내

- 증상 일기 카드 자동 생성
- 복용약·영양제 등록
- 준비물 체크리스트
- 예상 기간: 2~3주

### 우선순위 5: M6 공통 시스템 보강 (병행)

- M6.5 의학용어 일상어 자동 병기
- M6.6 면책 조항 일관 표시
- M6.7 개인정보 처리 (ISMS-P 사전 준비)
- M6.8 RAG 기반 응답 + 출처 추적

**총 예상 기간**: 13~16주 (약 3.5~4개월)

## 7. 기획서 v1 → v2 변경 사항 (Tracked Changes)

기획서 v2에 7곳의 tracked changes가 적용되어 있음. Word "검토" 모드로 열면 시각화됨.

1. 표지: "2026년 4월" 옆에 "(v2 — 2026년 5월 2일 개정)" 삽입
2. Ⅰ-1 한 줄 정의: "위치 기반 1차 의료 안내자" → "1차 의료 안내자"
3. Ⅰ-2 핵심 가치 제안 표: "위치 기반 1차 병원 추천 →" 삭제
4. Ⅲ-2-다 제목: "위치-시간-증상 3축" → "시간-증상 2축"
5. Ⅲ-2-다 본문: 위치 기반 표현 삭제 + 신뢰성 차별화 정책 명시
6. Ⅳ-1 5단계 사용자 여정 표: ④ "병원 추천" → "외부 지도 안내"
7. Ⅳ-2-다 알고리즘 섹션: 제목 변경 + 폐기 사유 3가지 명시 + 5개 가중치 항목 모두 삭제
8. Ⅸ-Phase 1: "응급도 + 위치기반 병원 추천" → "5단계 응급도 트리아지 + 자가관리 안내 + 카카오맵 외부 링크"

(*숫자 7로 시작했지만 실제 변경은 8곳입니다 — 기획서 v2 배포 시 참고)*

## 8. 검증된 작업 패턴 (반드시 유지)

### 8.1 보고 형식 의무화

Claude Code 또는 다른 AI 도구에 작업 지시 시 반드시 다음 형식을 요구:

- "통과/실패"만 표기한 보고는 받지 않음
- 패턴별 트레이싱 의무화 (어떤 패턴이 어떤 substring과 어떻게 매칭되었는지)
- 변경된 파일 목록 + 라인 수 명시
- 코드 발췌 포함

### 8.2 시나리오 기반 검증

- Type I + Type II 양방향 회귀 차단
- 임상 경고 검출 시나리오 + 일상 호소 차단 시나리오 + 복합 매칭 시나리오 모두 포함
- 신규 작업 시 반드시 기존 시나리오 회귀 검증 동반

### 8.3 절대 금지 사항 (모든 작업 공통)

- A-2 변환표(28개) 변경 금지
- red-flag-data.ts 매칭 패턴 변경 금지 (안정 상태)
- red-flag-classifier.ts 분류 로직 변경 금지
- 디바운싱 시간(1.5초)/최소 길이(5자) 변경 금지
- 자동 다이얼 코드 추가 금지 (절대, 어떤 상황에서도)
- 입력창 차단 로직 추가 금지
- onClick 핸들러로 tel:119 호출 추가 금지 (a 태그 href만 사용)

## 11. 새 채팅창에서 첫 작업 시작 안내

새 채팅창에서 본 인계 문서를 읽은 Claude는 다음과 같이 진행해야 합니다:

1. 본 인계 문서 전체를 읽고 medimentor 프로젝트 컨텍스트 파악
2. 사용자가 지정한 다음 작업이 무엇인지 확인
3. 해당 작업이 본 문서의 9개 핵심 결정사항(섹션 1.3)과 8.3 절대 금지 사항을 위반하지 않는지 확인
4. 작업 진행 전 반드시 다음 사항 확인:
   - 작업이 28개 모듈 중 어느 모듈에 해당하는지
   - 5단계 트리아지의 어느 단계에 해당하는지
   - 시나리오 기반 검증을 어떻게 적용할지
