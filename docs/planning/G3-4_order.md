### W-2. Vercel Blob 마이그레이션 범위 설계 + 동시성 분리 전략 (단계 3-α, read-only)

**전제**: W-1에서 보호 파일 교집합 없음 확인.

**설계 항목**:

1. **`@vercel/blob` 재사용** (G3-3에서 v2.3.3 도입 완료, 추가 설치 불요)
2. **동시성 분리 전략 선택** — Claude Code가 사용자 ACK 대기 양식으로 권고안 1건 명시:

| 전략 | pathname 예시 | 파일 수 (알파 5명 × 2주) | 동시성 위험 | 집계 복잡도 |
|---|---|---|---|---|
| **(α) 메트릭 타입별 분리** | `metrics/<type>.json` | 4 | 낮음 (타입별 격리) | 낮음 |
| **(β) 일별 분리** | `metrics/<YYYY-MM-DD>.json` | ~14 | 낮음 (시간 격리) | 중간 |
| **(γ) 타입 + 일별 결합** | `metrics/<type>/<YYYY-MM-DD>.json` | ~56 | 거의 0 | 중간 |

권고: **(α) 메트릭 타입별 분리** — 알파 5명 × 1~2주 트래픽에서 일별 분리 불필요, 단순성·집계 효율 양쪽 최적. 사용자가 (β)/(γ) 선호 시 단계 3-β 패치 시 반영.

3. fs API → Blob SDK 매핑 설계:
   - `appendFileSync(path, line + '\n')` → `get(pathname)` 으로 기존 내용 read → 새 줄 append → `put(pathname, body, { access: 'public', addRandomSuffix: false })`
   - `mkdirSync` → 불필요 (Blob은 디렉토리 개념 없음)
   - 빈 Blob 첫 적재 시: `get()` 404 → 새 내용으로 `put()`
4. **append 형식 보존**: 현 메트릭이 JSON Lines(NDJSON) 형식이면 동일 유지. JSON 배열 형식이면 동일 유지.
5. **G3-3과 동일 access policy**:
   - `access: 'public'` (v2.3.3 `private` deprecated 반영)
   - `addRandomSuffix: false`
   - PII 미저장 확인 (메트릭 4 타입의 페이로드 점검)
6. **환경 변수**: `BLOB_READ_WRITE_TOKEN` 그대로 사용 (G3-3에서 추가 완료, 신규 환경 변수 불요)
7. `.env.example` 갱신: 메트릭 적재용 pathname 예시 주석 추가 정도 (신규 키 불요)
8. **라우팅 무영향 확인** — 메트릭 모듈 ↔ 라우팅 모듈 의존 그래프 점검 (G3-3 동의 모듈과 동일 검증)
9. 단위 테스트 갱신 범위:
   - Blob SDK 모킹 (G3-3에서 도입된 모킹 패턴 재사용)
   - 기존 fs 모킹 제거
   - 동시성 분리 전략 검증 테스트 추가 (예상 +2~3건)

**산출 형식**:

```markdown

### 변경 대상 파일 목록 (예상 N건)
```
