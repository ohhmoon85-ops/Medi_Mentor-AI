## 1. 프로젝트 정체성

### 1.1 한 줄 정의 (v2 기획서 기준)

MediMentor AI는 환자에게는 "1차 의료 안내자"가 되고, 의사에게는 "24시간 옆을 지키는 임상 멘토"가 되어 주는, 전 세계 의료 지식을 통합한 양방향 AI 진료 지원 플랫폼이다.

### 1.2 medimentor 사용자 정체성 (E-1, 2026-05-02 재정의)

medimentor는 "노년층 대상 의료 AI"가 아니라 **"한국 가정 누구에게나 필요한 가정 주치의 안내자"**이다.

- **노년층**: 가장 취약한 1차 고려 대상이지만 유일 사용자가 아님. 빈발 증상 가중치 유지.
- **전 연령 시나리오 정식 지원**: 영유아·소아·청장년·임산부·노년 모두 커버.
- **가족 단위 3인칭 입력 정식 지원**: "내 아이가", "부모님이", "남편이" 등 입력자 ≠ 환자 시나리오. 단계 A·B의 1인칭 가정 로직(`capturedDemographics`)은 변경 없이 보존하고, M3-2/M3-3에서 3인칭 패턴 그룹 및 가족 인구학 라우팅을 별도 추가한다.
- **3인칭 가족 호칭 표준 목록** (M3-2-a-fix4에서 확정): 어머니, 아버지, 남편, 아내, 아들, 딸, 부모, 형, 동생, 언니, 할아버지, 할머니, 아이, 아기, 가족, **엄마, 아빠, 오빠, 누나** (구어체 4개 추가).

### 1.3 브로드 추천 정책 (G-1, 2026-05-02 도입)

medimentor는 닥터나우·굿닥의 단정적 병원 추천("이 병원으로 가세요")과 차별화하여 "안내자형 메시지"("이런 진료과들 중 가까운 곳으로 가세요")를 채택한다.

- 환자에게 `secondary_specialties`와 `tertiary_specialties`를 적극 노출
- 추천 문구 형식: "OO과를 우선 권합니다. ~한 경우 OO과·OO과도 고려하실 수 있습니다."
- "1차 의료 안내자" 정체성에 부합하는 환자 선택권 보장 정책
- M3-2의 50개 entries 매핑 작성 시 `secondary_specialties` 적극 활용 의무
- M3-3 추천 로직, M3-5 UI 구현에도 일관 적용

### 1.4 Critical 응급 라우팅 정책 (A-3, 2026-05-02 도입)

Critical 시나리오의 진료과 매핑은 다음 하이브리드 정책을 따른다.

- `primary_specialty`는 증상별 차등 (의학적 정확성 유지)
- M3-3 추천 로직에서 red_flag classifier critical 판정 시 `emergency:true` 진료과(EM)로 강제 라우팅
- 환자 안내 메시지: "119 응급실로 가세요. 내원 후 OO과 진료가 필요할 수 있습니다."
- `secondary_specialties`는 "응급 처치 후 follow-up 진료과" 의미 (B-3 정책)
- 예: SAH의 경우 secondary=[NS, NEU, REH] (수술 → 신경과 추적 → 재활)

### 1.5 현재 작업 범위

- **Care MVP 우선 개발 중** (옵션 D 채택)
- **Pro(의사용)는 Phase 2 이후 분리 진행** (면허 인증 인프라 등 진입 장벽 큼)
- 기획서 Phase 1 (M4~M9) 일정 안에 Care MVP 베타 출시 목표

### 1.6 의도적으로 "하지 않는 것" (변경 불가 결정사항)

| 제외 기능 | 사유 |
|----------|------|
| **위치 기반 병원 추천 알고리즘** | 닥터나우·굿닥과 차별화. AI가 특정 병원 추천 시 "광고비 낸 병원" 의혹 발생 가능 |
| 진단 단정 표현 | 의료법 제27조 무면허 의료행위 회피. "OO일 가능성이 있습니다"만 사용 |
| 처방 정보 환자 직접 제공 | 약사법·의약분업 위반 |
| 원격 진료 행위 | 의료법 제34조 회피 |
| 병원 후기·평점 알고리즘 | 의료광고법 시비 가능성 |

### 1.7 차별화 포지셔닝

- 기존 시장 플레이어: 닥터나우(병원 추천·예약), 굿닥(병원 검색)
- medimentor의 차별화: "증상 해석 + 진료과 안내 + 자가관리"에 정체성을 좁힘
- 의사용 Pro는 "환자가 우리 의원에 더 잘 준비된 상태로 오게 도와주는 도구"로 포지셔닝

## 3. 단계 A·B 검증 매트릭스 (마감)

총 127개 시나리오 100% 통과 + M3-1 + M3-1-fix 35개 통과 + M3-2-a (7회 사이클) 132개 통과.

### 3.1 양방향 회귀 차단 달성

| 오류 유형 | 대표 사례 | 차단 방법 |
|----------|---------|---------|
| Type II (놓침) | SAH 환자 → 일반 안내 | 4개 SAH 패턴 추가, 형태론 보강 |
| Type I (과경고) | "두통이 좀 있어요" → critical | 단독 키워드 제거, 복합 패턴만 유지 |

### 3.2 황 교수님 임상 자문 컨펌 4가지 UX 결정

1. **디바운싱**: 1.5초 정지 + 5자 미만 보류
2. **경고 강도**: 3단계 차등 + 음성 자동 재생 critical 한정
3. **입력 잠금**: 옵션 B (입력 유지) + 119 버튼 상시 노출
4. **119 직통**: 옵션 B (원탭 호출, 자동 다이얼 금지, tel:119 표준 링크)

### 8.4 작업 패턴 C — 임상 안전 등급별 차등 위임 (I-1, 2026-05-02 도입)

medimentor 작업 패턴은 임상 안전 위험도에 따라 다음 두 가지로 차등 적용한다.

**패턴 A — Claude(본 채팅) 사전 설계 + Claude Code 구현**:
- 적용 대상: critical (triage_level='critical') entries
- 사이클: 다회 (보강 발생 시)
- 사용: 본 채팅 Claude가 모든 시나리오·검증·정책을 사전 설계하여 Claude Code에 위임
- 사유: 환자 사망 위험 영역. 검증 누락이 생명 위협으로 직결.
- **상태**: M3-2-a critical 5개 안정화 종결 (2026-05-02). 향후 추가 critical entries 작업 시 동일 패턴 적용.

**패턴 C (= 패턴 B 위임 + 안전장치) — Claude Code 자율 시나리오 설계 + 자율 보강**:
- 적용 대상: urgent / outpatient / self_care (triage_level이 critical 외) entries
- 사이클: 1회 (entries 그룹별)
- 사용: 본 채팅 Claude가 작업 목표·정책·SOP·금지사항만 큰 틀로 지시. Claude Code가 entries별로 자율 시나리오 설계 + 자율 보강 + 자율 통과 검증
- 사유: 환자 사망 위험 영역 외. 형태론 결함이 환자 안전 위험으로 직결되지 않음.
- 안전장치 6가지:
  1. 작업 목표 + 정책 (A-3 / B-3 / E-1 / G-1) 명시
  2. 표준 작업 절차 (SOP) 명시
  3. F-3 / F-4-α/β/γ / F-5 절대 금지 헤더 의무 삽입
  4. 한국어 형태론 사전 점검 의무 (2.4 학습 결과 적용)
  5. 검증 표준: Type I + Type II 양방향 + 단계 A·B 회귀 + 통합 안정화 + F-4-γ 점검표
  6. 이터레이션 정책: entries별 검증 FAIL 발견 시 Claude Code 자체 보강 후 재실행
- 사용자 부담: M3-2 전체 합계 송부+회신 3회 (M3-2-b/c/d 각 1회씩)
- 본 채팅 Claude의 검증 역할: Claude Code 보고 회신 시 종합 통계만 점검 (entries 수 / FAIL 수 / 자체 판단 변경 사례 / F-4-γ 점검표 통과 여부). 환자 안전 위험 결함이 발견되지 않으면 통과 인정.
